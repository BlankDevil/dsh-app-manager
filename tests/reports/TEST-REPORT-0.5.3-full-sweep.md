## 3. 本轮发现并修复的问题

### 3.1 【真实回归】页面 `S9: no raw rgba in rule bodies` 失败

- **现象**：`smoke-features.mjs` 21/22，失败项 S9。
- **根因**：0.5.3 新增的 `.toast` 样式写了裸 `box-shadow: 0 6px 24px rgba(31,35,40,0.22)`，
  违反「所有颜色走 CSS 变量、便于亮/暗主题切换」的既有约定。
- **修复**：新增 token `--shadow-lg`（亮色 + 暗色两套）并在 `.toast` 中使用。
- **验证**：冒烟恢复 **22/22**。

### 3.2 【测试自身缺陷】TC-C01 断言过时（4 条路由 → 应为 7 条）

- **根因**：0.5.3 新增 3 条动作路由，用例仍断言 4 条 → 套件 50/51。
- **修复**：更新为 7 条并补全 7 个路径断言，注明动作路由的**行为**由 K 组覆盖。
- **验证**：套件恢复 **51/51**。

### 3.3 【测试自身缺陷】H 组两条用例环境敏感（Node 装在含空格路径即假失败）

- **现象**：用系统 Node（`D:\Program Files\nodejs\node.exe`）跑 H 组得 10/12；
  用无空格路径的托管 Node 跑得 12/12。
- **根因**（实测证据）：`execAsync` 在 Windows 走 `shell: true`，而 Node **不会为 cmd.exe 转义 argv**，
  于是含空格的 `process.execPath` 被拆开，子进程以
  `'D:\Program' 不是内部或外部命令` 秒退 —— 超时自然无从验证，表现为「假失败」。
- **修复**：测试内将解释器路径加引号后再交给 `execAsync`，并在文件里写明原因与实测数据。
- **验证**：**两种 Node 下均 12/12**。
- **遗留建议**：这是 `execAsync` 的**生产侧**局限（命令路径含空格时不可用）。
  当前只修了测试；若未来要探测装在 `Program Files` 下的应用，需在 `execAsync` 内
  对 `shell: true` 的命令加引号。已记入建议，未在本轮改动生产代码。

### 3.4 【静默覆盖缺口】G 组（拖拽）实际没跑

- **现象**：G 组输出 `SKIP: jsdom not installed` 并**退出码 0** —— 全绿但零覆盖，
  正是本仓库 CHANGELOG 里警告过的失败模式。
- **根因**：本机 `node_modules/jsdom` 是空目录（沙箱无法建符号链接的遗留），
  模块解析失败即跳过。
- **修复（环境侧）**：把 jsdom 27.4.0 装到隔离目录，用脚本自带的逃生口
  `DSH_TEST_JSDOM_DIR` 指向它。
- **验证**：G 组真实执行 **13/13**。
- **遗留建议**：CI 应显式确保 jsdom 可解析；建议把「SKIP 必须计入失败」
  作为一条元断言（见 §6）。

   （测试绝不改动用户机器），代价是「真实 `npm install -g` 的成功/失败路径」只由
   人工验证覆盖。
3. **非 Windows 平台仅逻辑级验证** —— I 组通过注入 `platform`/`execPath` 断言推导结果，
   Linux/macOS 的真机端到端未跑；`monitor` 在非 Windows 本就未实现（已知限制）。
4. **浏览器端到端（真实浏览器）未纳入本轮** —— 页面交互用 jsdom 行为断言 + 伪 HTTP 覆盖；
   真实浏览器手测已在开发期单独做过（开终端、升级徽章、确认框）。
5. **G 组在 jsdom 缺失时静默 SKIP（退出码 0）** —— 本轮以环境变量绕过，但机制仍在。
   建议增加元断言：任何 SKIP 必须计入失败，或至少输出到报告顶部。
6. **`execAsync` 对含空格命令的引用问题**（§3.3 的生产侧遗留）—— 未修生产代码。
7. 发现总数在多次运行间小幅波动（46 ↔ 47）：npx-cache 是活跃缓存目录，
   属环境噪声，非缺陷。
